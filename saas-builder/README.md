# Buy → Build → Replace

The recommended path is:

```text
Idea
  │
  ▼
Buy hosted services
  │
  ▼
Validate the business
  │
  ▼
Build your differentiator
  │
  ▼
Revenue / scale
  │
  ▼
Evaluate every dependency
  │
  ├── Keep SaaS
  │
  └── Replace commodity infrastructure
          │
          ▼
    Open source / self-hosted
```

Do not migrate simply because self-hosting is technically possible.

Consider replacing a SaaS dependency when there is a meaningful reason:

* Cost
* Scale
* Performance
* Data ownership
* Compliance
* Vendor risk
* Custom requirements
* Infrastructure control

# Build vs Buy

| Build                      | Buy                |
| -------------------------- | ------------------ |
| Core product logic         | Authentication     |

| Competitive workflow       | Email delivery     |
| Domain-specific AI         | SMS infrastructure |

| Proprietary data pipelines | Scheduling         |
| Product-specific search    | Customer support   |
| Core orchestration         | Accounting         |
| Differentiating automation | E-signatures       |

> **Can you build it?** Almost certainly.
>
> **Should you build it?** Only when doing so creates meaningful value for the business.

# Hosted First

This list prioritizes hosted services because they reduce infrastructure and operational overhead.

A hosted service can be the correct choice even when an open-source alternative exists.

The purpose is to optimize:

**time → validation → customers → revenue**

rather than:

**infrastructure → maintenance → operations → eventual product**

# Contribution Principles

This is a **curated list**, not a directory of every SaaS company.

A useful entry should:

* Solve a real problem.
* Be currently maintained.
* Have an official website.
* Be meaningfully useful to builders.
